# 首版 UI 观感门槛提纲（2026-10-30）

> 受众：G-master → UX + 美术细化。  
> 性质：**系统设计列门槛**，不代替 UX/美术 bible。  
> 玩法 SoT：`docs/游戏玩法.md`；技术口径：`docs/技术选型.md`。

## 1. 目的

- 首版必须达到可对外展示的「**非 demo**」产品观感。
- **先过门槛，再开功能开发**；功能开发以「过门槛样板屏」为闸。
- **新项目**：禁止以旧仓工程师灰盒 / 丑壳为参照「凑合」交付。

## 2. 适用范围（首版壳）

- 地图司令部壳
- 侧边情报消息流
- 危机暂停 / 确认窗
- HUD（日 + 未读 + 治下钱粮兵）
- 基础面板（方针、目标、情报详情等入口级）

## 3. 门槛条目（可验收一句标准）

| 维度 | 验收红线 |
|---|---|
| **Theme / 控件皮肤** | 全壳统一 Theme；禁止默认灰控件裸奔。 |
| **字体** | 中文可读层级清楚（标题 / 正文 / 辅助）；禁止系统默认混搭、无规划字号。 |
| **间距与栅格** | 边距 / 行距 / 对齐一致；禁止随手塞像素、错位堆叠。 |
| **色板** | 有限色板（背景 / 表面 / 文字 / 强调 / 危险 / 迷雾）；禁止随机工程师色。 |
| **动效** | 克制、可跳过、不挡危机说明；禁止炫技拖沓。 |
| **禁工程师灰盒** | 无未皮肤 Panel、无调试字当 UI、无占位方块当终态交付。 |
| **信息密度** | 消息流可读：双时间戳 / 来源 / 矛盾线索可见且不挤成一团。 |
| **认知迷雾** | UI 不泄规则层真相；禁止「可信度」分 / 条。 |

## 4. 签收顺序建议

1. **UX**：信息架构、组件态（默认 / 悬停 / 选中 / 禁用 / 危机态）
2. **美术**：Theme、色板、字体层级与关键皮肤
3. **系统设计**：不挡上述产出；只守玩法边界（迷雾不泄真、危机可解释等）
4. **功能开发闸**：先交付「过门槛样板屏」（司令部壳 + 消息流 + 危机窗 + HUD），再扩玩法功能

## 5. 本稿边界

本稿 = **门槛提纲**。细化稿（组件规格、视觉 bible、动效表）由 **UX + 美术** 产出；系统设计只维护本闸门与玩法/技术口径交叉引用。
