## 1. 目的与「非 demo」

- 首版必须达到可对外展示的「**非 demo**」产品观感。
- **先过门槛，再开功能开发**。功能 Build 以「过门槛样板屏」为闸（见第 2 节）。
- **新项目**：禁止以旧仓工程师灰盒 / 丑壳 / 案头卷宗为参照「凑合」交付。

### 什么叫过线（必须同时成立）

真人开 **Godot 真实窗口**（非 headless），第一眼觉得这是一款在做的策略游戏，不是引擎示例。

- 有项目 Theme。按钮、面板、输入、弹层都吃同一套皮。
- 字有层级。标题、正文、来源、双日戳一眼能分开。
- 间距有纪律。消息流像情报栏，不像临时列表。
- 状态看得见。默认 / 悬停 / 选中 / 禁用 / 危机态都能独立辨认。
- 壳是司令部，不是灰盒拼盘，也不是案头卷宗。
- HUD 能读：今天几号、有几条没看、治下还有多少钱粮兵。
- 雾有四档读法，过时快照不会被 UI 写成「已假」。

### 什么叫未过（任一即 fail）

- 灰盒占位当主界面。
- Godot 默认灰白 Button / Panel / LineEdit / PopupMenu 未经换皮出现在玩家截图里。
- 临时 `Label` 堆叠：同一字号、无边距、无卡片、无 Theme。
- 看起来像编辑器远程场景、debug overlay、或「先能点以后再美化」。
- 把案头卷宗当主壳或二级壳。
- 界面出现可信度分 / 条 / 星 / 「较可信」文案。
- 邻境被涂成当前确定事实，或 UI 替玩家裁定真假。

门禁绿、headless 通过、功能能点，**都不算**观感过关。观感只看真实窗口。

## 2. 适用范围与过门槛样板屏（功能 Build 闸）

### 管什么

- 新仓首版 **玩家能看见的全部 UI**。
- 默认路径（方案 B）：冷启动 → 地图司令部（证据板，**不是每天第一站**）→ 右侧情报流推异常 → 危机强制暂停窗 → 已知范围内选目标确认。
- 同壳下的 HUD、mapmode、图例、州详情卡、确认窗、挂机/危机条。
- 入口级基础面板：**方针、目标、情报详情**（同族 Theme，见第 4.1 节）。

### 不管什么

- 规则层 Hidden 真值、公式、结算、MapProjector 契约。
- 美术贴图生产与 shader 细节（走美术门槛）。
- 旧仓 `desk-*` 案头五面板。那是历史壳，**不是**首版样板。

### 过门槛样板屏 = 这四件套，缺一不可

| 件 | 玩家必须看见什么 | 大白话验收 |
|---|---|---|
| **司令部壳** | 地图主区 + 顶/边 chrome + mapmode/图例；羊皮纸同族，非灰盒、非案头 | 一眼是「对着舆图指挥」，不是引擎默认场景，也不是卷宗嵌窗 |
| **消息流** | 右侧可折叠情报栏；卡上有来源、双时间戳、主张、矛盾线索 | 展开约 280–320 宽；来源和两个时间都能读到，不挤成一团 |
| **危机窗** | 强制暂停；说明**为什么停**；最高层；不挡死说明正文 | 能指着文案说出停的理由；时间确实停了；减动效后仍能读完说明 |
| **HUD** | **日 + 未读 + 治下钱粮兵**（外加挂机/危机短句） | 不点开任何面板，就能报出「今天几号、几条没看、钱粮兵大概多少」 |

**闸门规则（硬）**

1. 样板屏未过 → **不得开玩法功能 Build**（出征结算、探子招募、方针 AI 等一律停在闸外）。
2. 样板屏必须是 **真实窗口** 里能点的四件套，不是静帧拼图，不是 headless 绿。
3. 四件套必须同族 Theme。危机窗不能是默认 `AcceptDialog`，消息流不能是裸 `ItemList`，HUD 不能是一排默认 Label。
4. 过闸只证明「壳能卖相」；不证明玩法系统已齐。过闸之后才扩功能。

日循环已定 **方案 B**（`docs/游戏玩法.md`）：平时议会挂机慢走；消息流只推异常；危机强制暂停。地图是证据板，不是每天第一站。

## 3. 签收顺序（不可颠倒）

与 QS 提纲一致，只把职责写死：

| 步 | 谁 | 签什么 | 未签后果 |
|---|---|---|---|
| **1** | **UX**（本稿） | 信息架构；组件态（**默认 / 悬停 / 选中 / 禁用 / 危机态**）；字段（双时间戳 / 来源 / 矛盾）；样板屏布局；语义色用途 | 美术不得靠猜「未读是不是该用红」；程序不得先铺灰盒通流程当交付 |
| **2** | **美术** | Theme、色板终值、字体文件、关键皮肤、雾四档观感参数 | 不得把默认灰白当皮；色值以 art 门槛为准 |
| **3** | **系统设计** | **不挡** UX/美术产出；只守玩法边界（迷雾不泄真、危机可解释、无可信度、点卡非下令） | 不得以「系统还没接」为由让样板屏继续灰盒 |
| **4** | **功能开发** | 先交「过门槛样板屏」（司令部壳 + 消息流 + 危机窗 + HUD），**再**扩玩法功能 | 样板未过 = Build 闸关 |

一句话： **UX 锁态和字段 → 美术上色上字上皮 → 系统守玩法 → 功能才许开干。**

## 4. 八维门槛（对齐 QS，可验收）

QS 提纲八维在此逐条写成数字和禁令。一条不达标，样板屏不得过闸。

### 4.1 Theme / 控件皮肤

首版必须有一份玩家 Theme（或等价全局 StyleBox 套件）。新控件默认吃 Theme，不允许每个脚本手写一套灰皮。

精确 hex / StyleBox 数字以美术稿为准。UX 只锁 **必须换皮、必须同族、必须有五态**。

#### 五态（UX 先签，美术后上色）

每个可点控件至少这五态，且 **不靠单一颜色** 区分：

| 态 | 玩家应读到 | 必须另有的非色通道 |
|---|---|---|
| 默认 | 可点、安静 | 细金褐边 + 纸底 |
| 悬停 | 「指着它」 | 80–120ms 内提亮或描边加粗；指针仍是选择 |
| 选中 | 「正在对这个做事」 | 边或衬 + 字重；地图选中州必须在**地图层**高亮 |
| 禁用 | 「现在点不了」 | 变淡 **且** 可见原因（文案或常驻提示），不能只变灰 |
| 危机态 | 「世界停了，先处理这个」 | 强调赤 + 停顿 + 「危机打断」文案；**不可**与未读共用同一套红点 |

Focus 与 Hover **两套样子**。键盘操作必须看得见焦点。

#### 不得裸默认

| 控件 | 底线 | 未过的样子 |
|---|---|---|
| `Button` | 羊皮纸扁皮；五态可辨 | 灰底蓝字、默认 focus 蓝框当交付 |
| `Panel` / `PanelContainer` | 浅纸底 + 细金褐边；圆角 4–8 | 白/灰矩形、无边、厚 bevel |
| `LineEdit` / 检索框 | 同族纸底；焦点边可见；placeholder 走辅助色 | 系统白输入框 |
| `PopupMenu` / `PopupPanel` / 下拉 | 与面板同族；最高层时不被地图吞 | 默认灰弹出条 |
| 消息卡 | 卡片容器，不是裸 Label | 一列黑字贴在地图上 |
| 危机窗 / 确认窗 | 浅模态纸；有标题区 / 说明区 / 按钮区 | 临时 `AcceptDialog` 灰窗 |
| 滚动条 | 低调，溢出才出现 | 粗系统条抢视觉 |
| HUD 芯片 | 同族小纸片；日 / 未读 / 钱粮兵可扫 | 默认 Label 贴窗口顶 |

#### 基础面板必须同族 Theme

方针、目标、情报详情（以及后续势力 / 军务 / 资源弹层）**不必**首版一次做完 icon kit，但必须：

- 色板 + 控件皮 + 字号层级与司令部壳 **同族**；
- 开法一致：从壳入口打开，盖在司令部之上，关掉仍回证据板；
- **禁止**各自发明深色霓虹皮、禁止做成案头卷宗分页。

方针面板还要让「当前方针」在挂机时于 HUD 或壳上可感（短句即可），不能只藏在二级菜单里。

#### 必须 / 禁止（Theme）

- 圆角约 4–8。不要 16+ 的 App 卡片，也不要 0 圆角的 debug 块。
- 阴影可有一层轻投影。不要厚拟物、不要玻璃仪表盘。
- 主按钮和次按钮有差别：确认是主，取消是次。不能两个一样灰。
- **禁止**灰盒占位、彩色 `ColorRect` 当面板。
- **禁止**卷宗窗框、嵌窗舆图、案头木纹当默认壳皮。
- **禁止**「先用默认控件通流程，皮肤下个迭代再补」当作首版交付理由。

### 4.2 字体

目标分辨率按 **1280×720 窗口** 验收（允许略大，字号关系不变）。单位：px。字重：标题 Medium，正文 Regular，辅助 Regular。不要全 Bold。

字体文件由美术定；UX 锁层级。中文必须可读，不允许首版截图里中文方框或 fallback 西文体当正文。

| 层级 | 字号 | 字重 | 行高约 | 用在哪 |
|---|---|---|---|---|
| 窗标题 | 20–22 | Medium | 1.2 | 危机窗标题、确认窗标题 |
| 区标题 | 18 | Medium | 1.2 | 情报流标题、详情卡州名、方针/目标窗标题 |
| 卡标题 | 16 | Medium | 1.25 | 消息卡标题 / 摘要第一行 |
| 正文 | 14–15 | Regular | **1.40–1.50** | 消息正文、危机说明、确认窗可知摘要 |
| 辅助 | 12 | Regular | 1.30 | **来源、双时间戳、消息类型、HUD 日、图例、钱粮兵单位** |
| 角标 | 11–12 | Medium | 1.0 | 未读数 |

#### 关系（可测）

- 区标题必须 **大于** 卡标题至少 2px。
- 卡标题必须 **大于** 正文至少 1px。
- 来源 / 双时间戳必须 **≤ 12**，走辅助色，不得做成第二标题。
- 同一张消息卡里字段分层，禁止四行同字号（见 4.7）。
- 中文正文按流宽折行，不要拉满整屏。

#### 禁止

- 全界面默认 16px Label 一锅炖。
- 用字号暗示可信度（「更真的情报更大」）。
- 日戳做成倒计时或章历进度条。
- HUD 钱粮兵用特大数字仪表盘风，抢过危机说明。

### 4.3 间距与栅格

用 8px 网格。能对 8 就对 8。禁止随手塞像素、错位堆叠。

| 项 | 数字 | 判据 |
|---|---|---|
| 窗口安全边 | 至少 16 | chrome 不贴死窗口边 |
| 面板内边距 | 12–16 | 流、图例、危机窗、方针/目标/详情内边 |
| 消息流展开宽 | **280–320**（默认按 300） | 量抽屉外沿，不含折叠条 |
| 消息流折叠后宽 | ≤ 120 | 折叠后读图面积明显回来 |
| 消息卡内边距 | **10–12** | 字不顶边、不空成广告卡 |
| 卡与卡间距 | 8 | 能分开，不散成孤岛 |
| 卡最小高度 | 80–96 | 来源 + 双时间戳 + 标题 + 两行摘要放得下，不挤成一条 |
| 按钮高度 | 32–36 | 确认/取消、mapmode 钮同量级 |
| 标题与正文间距 | 6–8 | 分组清楚 |
| 正文段落间距 | 8 | 多段摘要可扫 |
| HUD 芯片内边距 | 8×6 | 日 / 未读 / 钱粮兵能点能读 |
| HUD 芯片间距 | 8 | 三组信息可扫，不粘成一串 |

**过稀**：大片空白、卡高超过 140 却只有一行字、按钮漂在窗底中间 → fail。

**过挤**：字贴边、两张卡边线相贴、来源和双时间戳撞行、确认/取消挤成一条 24px 高 → fail。

**密度目标**：展开消息流后，主屏仍应一眼能读河东 12 州轮廓。流是侧栏，不是半屏 Inbox。

### 4.4 色板语义（值跟美术，用途跟 UX）

**色值以 art 为准。** 下面 hex 是交叉引用用的参考，落地以 `design/art/2026-10-30-ui-art-quality-bar.md` 及 `palette_B_medium` / `chrome_tokens_B` 为准。美术换 hex 可以；**换语义不行**。

参考 hex（非终值）：

| 用途 | 参考 |
|---|---|
| 纸面 | `#E8DCC4`～`#F3E6D0` |
| 确认/危机窗纸 | `#F7EDDC` 一带 |
| 正文 | `#3A342C` |
| 辅助 / 次要 | `#6A5E50` |
| 描边 | `#C4A574`；加强 `#A8844E` |
| 激活强调 / 危机 | `#C45C4A` |
| 未知雾底 | `#6E7064` 冷灰绿 |
| 河 | `#7EC8D4` |
| 势力例 | 晋 `#6B9EB2` · 昭义 `#BDA061`（政治色强度中：≈0.70） |

#### 语义表（UX 锁死）

| 语义 | 玩家应读到 | 用法 | 禁止当成 |
|---|---|---|---|
| 成功 | 「这步做完了」 | 下令已确认、关窗回地图。克制金褐/墨色勾 + 文案。可短闪，不常驻绿勾 | 这条情报是真的 |
| 警告 | 「要留神，仍可能是旧闻或风险」 | 过时快照、资源紧、邻境仅有旧报。暖褐 / stale 斜线 +「过时/旧闻」 | 已证伪、已失败 |
| 危机 | 「世界停了，必须处理」 | 强制暂停。强调赤 + 停顿遮罩 + 明确文案「危机打断」+ **停的理由** | 未读角标、普通急报 |
| 未读 | 「你还没看」 | 角标数字 + 字重 + 卡底略深。必须有非颜色通道 | 更紧急、更可信 |
| 迷雾 | 「你不知道」 | 冷灰绿雾；邻境无投影就不涂政治色 | 加载失败、空数据 bug |
| 治下 | 「这是你家，钱粮兵按可见规则可看真值」 | 粉彩政治洗 + 清晰州名；HUD 给治下钱粮兵 | 全知仪表盘 |
| 邻境 | 「这是别人或未知」 | 雾，或「据某日 · 某来源」旧快照 | 当前确定兵力/归属 |

#### 对比度底线（口语）

- 隔一臂远，仍能认出：区标题、未读点、危机条、HUD 日与钱粮兵。
- 浅纸上禁止再铺浅灰正文。正文必须是深墨，辅助才用灰褐。
- 地图上的州名压在政治色/雾上仍能读。读不清就加底衬，不许靠玩家猜。
- 选中边、未读点、危机强调，不能只靠 5% 色差。要有形状或字重帮忙。
- 红绿色盲时：未读仍有点/字重；危机仍有「停」和文案；治下/邻境仍有雾 vs 洗的差别。

#### 禁止

- **可信度色**：绿真红假、星级、进度条、热力「靠谱度」。
- 用更饱和的政治色表示「情报更新所以更真」。
- 成功绿和危机红拿来给消息卡打分。
- 无来源的系统蓝信息条冒充探报。
- 随机工程师色、霓虹、debug 色块当玩家交付。

---

### 4.5 动效

动效是反馈，不是表演。平时克制。危机才准停顿加重。

| 类 | 时长 | 必须有反馈 | 禁止 |
|---|---|---|---|
| 悬停 / 按下 / 焦点 | **80–120ms** | 皮的态切换 | bounce、ripple、发光拖尾 |
| 消息流折合 | **180–280ms** | 宽度变化，地图读区跟着让/还 | 弹性晃、旋转 |
| 确认窗 / 危机窗开关 | **150–220ms** 淡入；位移 ≤ 8px | 打开即最高层、输入进窗 | 从屏幕外飞入、长距离掉落 |
| 点卡定位 | **200–350ms** pan | 州高亮接上 | 拉军令线、镜头甩飞 |
| 新卡进流 | ≤ 180ms 顶置 | 未读数 +1；已展开的详情不被抢走 | 强制展开、全屏闪 |
| 下令成功 | ≤ 180ms | 窗关、回地图；之后回声走消息卡 | 烟花、盖章长动画 |
| **危机打断** | **200–400ms 清晰停顿** | 时间感停住；可短压暗；**标题和理由正文落下后必须可读** | 闪红警报循环、粒子拖尾、连续震动、动画盖住说明 |
| 跨日（若有） | ≤ 800ms | 日戳切换 | 日常挂机播 1.5s 华丽过场 |

#### 可跳过 / 减动效（必须）

- **可跳过**：任意过场、跨日、窗动画，在播放中点、按 Esc 或「跳过」，立即切到终态。危机**停顿感**可以缩短，**不可跳过「必须面对打断」本身**（玩法：危机强制停不可关）。
- **减动效**（系统或游戏内开关）：一律 cut 或 ≤ 80ms fade。不许弹簧、不许长停顿循环。
- **减动效仍可读**：关动画后，五态、未读点、危机理由、双时间戳、HUD 钱粮兵全部仍在。动画不得当唯一状态通道。
- **不挡危机说明**：危机窗标题、停的理由、可知选项，在动效期间和减动效后都必须能读完。禁止全屏闪红、粒子、震动把正文盖住。

#### 危机停顿感（必须可玩）

1. 挂机推进停下。玩家能指着 HUD 说「停了」。
2. 有一拍静（200–400ms），再让危机说明可读——**说明优先于特效**。
3. 地图还在，仍是证据板，不是切到另一套案头。
4. 处理完之前，不偷偷恢复慢走。
5. 窗上必须写清**为什么停**（敌军出现在已知区 / 城失联 / 阴谋暴露等，只用当前可知信息）。

#### 禁止花哨

- 拖尾、bloom 按钮、霓虹描边呼吸。
- Toast 飞入当主反馈。
- 炫技拖沓超过上表时长。

### 4.6 禁工程师灰盒

下列任一出现在玩家窗口 / 首版截图 = 直接 fail：

- 未皮肤 `Panel` / 默认灰白 Button / 白底系统输入框。
- 调试字当 UI（节点路径、枚举 raw 名、`Hidden`、`truth_refs`、资格码）。
- 占位方块、彩色 `ColorRect`、棋盘格当终态交付。
- 临时 Label 堆叠充当消息流、危机窗或 HUD。
- 把编辑器远程场景、FPS 叠层、navmesh 调试留在玩家壳。

灰盒可以存在于开发分支内部。**不能**作为样板屏签收对象，也不能「先过功能再补皮」。

### 4.7 信息密度（消息流可读）

消息流是异常情报栏，不是邮件、不是日程表、不是 debug log。

#### 一张卡必须同时露出（不点开详情也要看见）

| 字段 | 玩家应读到 | 怎么摆 | 禁止 |
|---|---|---|---|
| **主张 / 标题** | 「这张卡在说什么」 | 卡标题 16 Medium；一行，溢出省略 | 用标题写「建议先打 X」 |
| **来源** | 「谁说的 / 哪条渠道」 | 辅助 12；与时间戳同一行或紧邻 | 无来源的系统蓝条冒充探报 |
| **双时间戳** | **事件发生日** vs **送达日** | 辅助 12；两个都可见；若同一天可写成「发生 Day 12 · 当日送达」，**不得只留一个** | 只给一个「时间」让玩家猜是发生还是送到；做成倒计时 |
| **矛盾线索** | 「和哪张卡打架」 | 短标签或「与另一则冲突」入口；并列，不合并 | 合成「综合军情」；标「此条为假」 |
| 未读标记 | 「还没看」 | 点 / 字重 / 「未读」；可加角标 | 只把卡涂红 |
| 过时标记（若 stale） | 「这是旧闻」 | 「过时/旧闻」+ 发生日 | 写成「已假」「已证伪」 |

点开详情后可加：完整正文、关联州、并列的矛盾卡列表。详情仍不代判。

#### 双时间戳怎么写（大白话）

- **发生**：这件事据称在哪一天发生。
- **送达**：你的耳目哪一天把话送到司令部。
- 两者可以差很多天。差多少是给玩家的线索，不是 UI 打分。
- HUD 的「日」是**当前世界日**，不要和卡上的发生/送达混成一个字段。

#### 密度禁令

- 四行同字号挤成一团 → fail。
- 来源、发生、送达互相重叠 → fail。
- 为了「干净」丢掉双时间戳或来源 → fail。
- 矛盾卡被折叠进「已综合」→ fail。

---

### 4.8 认知迷雾（四档语义）

UI **不泄规则层真相**。禁止「可信度」分 / 条 / 星 / 文案。雾的视觉参数跟美术；**四档分别让玩家读到什么**跟 UX。

| 档 | 玩家应读到 | 界面怎么表现（语义） | 明确不是 |
|---|---|---|---|
| **unknown** | 「我不知道那里」 | 浓雾冷灰绿；无政治真值涂色；无精确兵力 | 加载失败、没做完的灰块 |
| **partial** | 「知道一点，远不是全知」 | 轻雾、降清晰；可知字段有限；缺的就缺，不补假数 | 「半真」；用透明度当可信度 |
| **stale** | 「这是旧报，当时可能对，现在不一定」 | 陈旧洗 ± 细斜线；摘要必须带来源 + **发生/送达日** | **≠ 证伪**；≠ 已失败；≠ 可以当没看见 |
| **clear** | 「治下可见规则内，这是你能当账本用的」 | 无 FogOverlay 洗；治下钱粮兵可进 HUD | 邻境突然全知；通视 CK3 |

#### stale ≠ 证伪（写三次都不够，再写一次）

过时快照只说「旧」。UI 不得写「假」、不得打叉、不得把 stale 卡自动归档为已否定。矛盾卡并列；玩家自己判。

#### 迷雾红线（与玩法一致）

- 邻境只给雾或带来源+日戳的旧快照。禁止 Hidden 真值、`truth_refs`、精确未知兵力/金库。
- 迷雾外不弹「敌军正在围 X」这种精确危机卡；最多弱信号（「某方向久无信」）。
- 详情 / tooltip **禁止**接 `confidence`、Hidden、资格码。
- 图例可含「未知 / 旧报」，**不含**可信度图例。
- 脏情报可以制造假危机或掩盖真危机——仍走可见卡，不泄真。

## 5. HUD（日 + 未读 + 治下钱粮兵）

HUD 是样板屏四件套之一。不点开面板也必须能读。

| 槽 | 显示 | 语义 | 禁止 |
|---|---|---|---|
| **日** | 当前世界日（短，如「第 12 日」） | 现在走到哪一天 | 章进度条、剧本日历、beat 倒计时 |
| **未读** | 未读条数角标；可点开流 | 你还没看的异常 | 用红角标表示危机；未读 = 更可信 |
| **治下钱粮兵** | 三组可知真值：钱 / 粮 / 兵（治下合计或主账，口径跟玩法「知道：治下钱粮兵」） | 这是你家的账，不是邻境估计 | 邻境兵力、忠诚条、可信度、把三组做成巨大仪表盘挡住读图 |
| 运行态短句 | 「议会进行中」或「危机打断」 | 挂机 vs 强制停，一眼可分 | 看起来像死机；危机只闪红不改文案 |

补充规则：

- 钱粮兵只反映 **治下可知**。邻境缺数就空着或走消息卡旧报，HUD 不编。
- 资源紧可用警告语义（暖褐 +「紧」短句），不得把钱粮兵数字变红装可信度。
- HUD 不放日程、不放探子名单、不放「建议」。
- 方针可感：可用极短附属字（如「方针：稳边」），仍同族芯片，不另开一套皮。

## 6. 壳级布局（样板屏怎么摆）

默认壳只有这一套：**地图主区 + 侧边情报流 + HUD chrome + 必要时的确认窗 / 详情卡 / 危机层**。

```
┌──────────────────────────────────────────────┬─────────────┐
│  HUD：日 · 未读 · 治下钱粮兵 · 挂机/危机      │ 情报流       │
│                                              │ 280–320     │
│              地图司令部（读图主区）            │ 可折叠       │
│                                              │ 消息卡列表    │
│     详情卡避让州心 ──┐                       │ 来源+双日戳  │
│                     │                       │ 矛盾线索     │
│  mapmode / 图例（不挡州心）                    │             │
└──────────────────────────────────────────────┴─────────────┘
        危机窗 / 确认窗：最高层，居中偏上，盖住流与 chrome
        说明正文必须完整可见；动效不得挡住理由
```

### 必须

- 地图主区可读。消息流展开时，主区仍能扫到河东 12 州 + 潞州锚轮廓。
- 消息流在右侧，可折。折叠只留窄条/钮 + 未读角标。
- 危机窗 / 确认窗最高层。开着时盖住消息流、mapmode、详情卡。底层不可改选目标。
- 详情卡避让读图：不盖州心、不盖主要操作带、不把地图缩成一条缝。
- 方案 B 节奏在壳上成立：平时慢走，异常进流，危机打断。不要每天开场强制把镜头甩到「今日第一站」。
- 基础面板（方针 / 目标 / 情报详情）从壳入口进，同族，关掉回司令部。

### 禁止

- 案头卷宗作主壳或二级壳（含 Inbox 页、嵌卷宗窗舆图、「返回案头」）。
- 消息流做成半屏邮件客户端。
- 危机窗当第二消息流、在窗里读整份文书而把「为什么停」挤没。
- 地图上的军令线、可拖拽行军编辑器。
- 把图例做成铁轨工具条，或把 chrome 堆到挡州名。

点消息卡 = 定位关联州（pan + 高亮）。**不等于下令**。下令仍是选目标 → 确认。未知邻境仍允许下令（迷雾不是门禁）；失败短句只说玩家能理解的原因。

## 7. 状态反馈（组件态补表）

每条都必须 **不靠单一颜色**。至少再加一样：描边、字重、文案、图标、停顿。

| 状态 | 必须发生什么 | 不许发生什么 |
|---|---|---|
| 选中州 | 地图层高亮该州（边或衬），州名可辨；命令入口对该州生效 | 只改消息流选中色；不画军令线 |
| 悬停州 / 悬停卡 | 80–120ms 内提亮或描边；指针仍是选择，不是下令 | hover 就弹出确认窗 |
| 按下 | 皮变 pressed；松手才触发 | 按下拖出军令线 |
| 未读 | 角标计数；卡标题偏重；非色标记（点或「未读」） | 只把卡涂红；红 = 更真 |
| 已读 | 字重回 Regular；点消失；卡仍可点定位 | 已读被删掉或标成「已核实」 |
| 禁用 | 可见原因（如无兵可调） | 只变灰、点了没反应也没说明 |
| 挂机中（方案 B 平时） | HUD 常驻「议会进行中」或等价短句；日推进缓慢可感；新异常进流涨未读，**不**强制展开流 | 看起来像死机；自动打开确认窗；每天把玩家甩到地图当第一站 |
| 危机强制停 | 挂机停；有停顿感；**理由正文可见**；玩家必须先面对打断再回慢走 | 只闪一下红；时间还在走；用 toast 替代打断；动画挡住说明 |
| 确认 | 主按钮明确「确认」；提交后关窗回地图；规则去结算 | 无确认一键派出 |
| 取消 | 关窗、保留选中、不提交 | Esc 没反应；取消却把令送出去 |
| 失败短句 | 窗内可见、中性、只说玩家已能知道的原因 | 资格码、Hidden 兵力、伪报成功 |

## 8. 硬红线清单

首版违反任一条 = 观感与产品双 fail。与 QS 八维 + 玩法口径对齐。

1. **迷雾不泄真**：邻境只给 unknown/partial/stale，或带来源+双日戳的旧快照。禁止 Hidden 真值、`truth_refs`、精确未知兵力/金库。
2. **无可信度**：禁止分、条、星、百分比、「较可信」「建议信谁」。
3. **UI 不代判**：矛盾卡并列；**stale ≠ 证伪**；不合并成「综合军情」；不写「建议先打 X」。
4. **无案头主壳 / 二级壳**：晨禀等只进消息卡。禁止卷宗嵌窗当样板。
5. **无灰盒交付**：无 `ColorRect` 占位主界面、无默认灰白控件、无临时 Label 堆叠当首版。
6. **无 Godot demo 皮**：玩家截图里不许一眼看出没换 Theme。
7. **下令必须确认**：选目标 → 确认。点卡不是派出。无军令线。无一键派出。
8. **无编剧日历壳**：消息流不是 DayN 日程表。HUD 日戳不是章进度条。
9. **危机停、挂机走**：平时议会挂机不得伪装成卡死；危机不得只做皮肤闪红而时间继续走；危机说明不得被动效挡住。
10. **知情权反 CK3**：壳可以更 CK3，数字和雾不能变成全知 CK3。
11. **样板未过不开功能 Build**：司令部壳 + 消息流 + 危机窗 + HUD 未在真实窗口过闸前，不得扩玩法功能。
12. **基础面板同族**：方针 / 目标 / 情报详情不得另起灰皮或案头皮。

## 9. 首版验收 checklist（按 QS 八维）

在 **真实 Godot 窗口** 里用人眼判。每条只许 pass / fail。一条 fail，样板屏未过，功能 Build 闸不开。

### A. Theme / 控件皮肤

- [ ] 第一眼不是引擎默认灰白 demo。
- [ ] Button / Panel / LineEdit / Popup / 滚动条都吃项目皮，不是裸默认。
- [ ] 默认 / 悬停 / 选中 / 禁用 / 危机态五态可辨，且不单靠颜色。
- [ ] 确认主按钮与取消次按钮有差别。
- [ ] 方针 / 目标 / 情报详情与司令部同族 Theme（有入口的都要查）。
- [ ] 危机窗不是默认 `AcceptDialog`。

### B. 字体

- [ ] 标题 / 正文 / 来源与双日戳三层能分开，字号符合 4.2。
- [ ] 中文无方框、无西文 fallback 当正文。

### C. 间距与栅格

- [ ] 消息流展开宽约 280–320；折叠后地图明显变大。
- [ ] 消息卡有 10–12 内边距，不贴边、不空洞。

### D. 色板

- [ ] 纸面羊皮纸粉彩同族；无随机工程师色、无霓虹。
- [ ] 治下与邻境一眼可分（洗 vs 雾/旧报），不是同一张全知涂色。
- [ ] 正文在纸面上隔一臂仍可读。
- [ ] 没有任何可信度条/分/星/「较可信」。

### E. 动效

- [ ] 控件态在 80–120ms 内有反馈。
- [ ] 没有拖尾、弹跳、霓虹呼吸、飞入 toast。
- [ ] 危机打断能感到「停了一拍」，且**理由正文不被挡住**。
- [ ] 过场可跳过；打开减动效后五态/字段/危机说明仍可读。

### F. 禁工程师灰盒

- [ ] 没有灰盒占位当主界面。
- [ ] 没有临时 Label 堆叠充当消息流、危机窗或 HUD。
- [ ] 没有调试字、节点路径、Hidden、资格码出现在玩家壳。

### G. 信息密度

- [ ] 消息卡同时可见：来源、**发生时间、送达时间**、主张。
- [ ] 矛盾线索可见且不挤成一团；UI 不裁定谁真。
- [ ] 过时快照文案是「过时/旧闻」，不是「已假」。

### H. 认知迷雾

- [ ] 能指出 unknown / partial / stale / clear 的差别（样板至少覆盖 unknown、stale、clear）。
- [ ] stale 没有被写成证伪。
- [ ] 未知邻州是「不知」，不是灰数据洞，也不是被填满的政区。
- [ ] 界面无 Hidden、`truth_refs`、confidence。

### 样板屏四件套（闸）

- [ ] 冷启动进地图司令部，不是案头。
- [ ] 找不到案头主壳或二级壳入口。
- [ ] 右侧消息流可折；确认/危机窗在最高层。
- [ ] HUD 不点开即可读：**日 + 未读 + 治下钱粮兵**。
- [ ] 详情卡不挡州心和主要读图区。

### 状态与下令

- [ ] 选中州在地图上可辨。
- [ ] 未读 / 已读能分，且不只靠颜色。
- [ ] 点卡会定位州，但不会派出。
- [ ] 出征/调防必须过确认；取消保留选中、不提交。

### 方案 B 节奏

- [ ] 平时能看出「议会挂机 / 慢走」，不像死机。
- [ ] 异常进消息流，涨未读，不强制抢读图。
- [ ] 危机强制暂停：有停顿感，时间停，**说明理由**，文案明确。
- [ ] 地图仍是证据板；处理危机不必切回案头。

### 红线抽检

- [ ] 无军令线、无 DayN 日程束、无「建议先打 X」。
- [ ] 无可信度、无案头壳、无默认灰白、无灰盒。
- [ ] 样板四件套齐，才谈论功能 Build。

## 10. 给各角色的用法

| 角色 | 怎么用本文件 |
|---|---|
| UX | 本稿就是签收单。组件态、字段、样板布局改了要改本稿日期并同步 QS 闸门。 |
| 美术 | 色/皮/雾以 `design/art/2026-10-30-ui-art-quality-bar.md` 生产；语义用途来问本文件。装饰色让路给未读/危机/迷雾四档。 |
| UI 程序 | 先套 Theme 和字号表，再接线。新 Panel/Button 不进默认灰皮。样板四件套先做完。 |
| 主程 | 功能能跑不算过。截图前自查第 9 节。别把 debug overlay 留在玩家壳。样板未过不开功能 Build。 |
| 系统设计 | 守玩法边界，不挡 UX/美术。不要求本文件写公式。 |
| G-master | 首版签收看第 9 节人眼清单，不看 headless 绿。 |

## 11. 一句话红线
